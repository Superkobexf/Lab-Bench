# Lab-Bench 代码统一说明

更新日期：2026-08-30

## 统一结果

`Lab-Bench` 仓库是后续唯一功能开发主线。它现在同时包含：

- 原 Lab-Bench 的后端、账号、目标计划、合同版本管理、合同解析/OCR 和倒数日。
- 原云端实验室的进展档案合并、科研自动化和 NATURE Skills 入口。

本机旧的 `云端实验室` 目录保留为历史版本与真实数据材料目录，不再双向同步前端代码。不要删除其中的学生档案、成果 PDF、微信小程序历史工程或已打包版本。

## 数据边界

- 公开仓库只能放虚构示例数据，不能复制真实学生、联系方式、成果证明、经费、合同或本地文件路径。
- 老版 JSON 可由 Lab-Bench 的“数据”页面导入；服务端只导入白名单集合。
- `automationPipelines` 按 `studentId` 归属。学生账号只读取和修改自己的流程；导师读取全组并负责删除和最终审核。
- NATURE Skills 是外部 Apache-2.0 项目入口。Lab-Bench 不打包上游代码，不把课题组数据发给上游。

## 后续开发规则

1. 新功能只改 Lab-Bench，并同时检查服务端集合白名单、角色权限、i18n 词典和浏览器运行态。
2. 需要导入真实数据时，从旧目录读取后写入本地/自建服务器数据库，不写回 Git 仓库。
3. 发布前分别验证导师账号、学生账号、中文、英文、导入导出、合同 OCR 和科研自动化流程。
4. `云端实验室` 的静态版只做历史回看；发现旧版更好的交互时，按功能迁移，不再复制整份代码。

## 回滚

本次统一不删除旧目录。若新版本出现问题，可以继续从旧静态版读取历史数据，或从 Lab-Bench 的 JSON/SQLite 备份恢复；不要用旧前端覆盖 Lab-Bench。
