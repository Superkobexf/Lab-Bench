# 回归测试

这套测试守的是**改坏了会伤到学生的那几条线**，不是追求覆盖率。

```bash
cd server && python3 -m pytest tests -q
```

需要 `pytest` 和 `httpx`（`pip install pytest httpx`）。测试用临时数据库，
不碰任何真实数据。

## 每个文件在守什么

| 文件 | 守的线 |
| --- | --- |
| `test_authz.py` | **归属判定必须以库内数据为准，不能信请求体声称的 studentId。** 这条线被破坏过一次：学生只要 PUT 到别人的记录 id、把 studentId 填成自己，就能覆盖同学的周进展。那个洞是写测试时撞出来的，不是 review 看出来的。 |
| `test_files.py` | **只有真图片能内联，其余强制下载。** 任何能被浏览器当 HTML 解析的东西从本域内联返回，等于在应用 origin 里执行脚本。SVG 尤其危险——能带 `<script>`，看着却像图片。 |
| `test_extract.py` | 合同抽取只认「日期 + 节点词」，签署日期和证件有效期不进日程；同句里的多个日期要拿到各自的分句标题；PDF 换行必须还原。 |
| `test_workflow.py` | 旧备份导入、合同上传→确认→倒数日、删除→回收站→连带恢复、口令重置与登录锁定。 |

## 为什么值得维护

多个人和多个 AI 在交替改这份代码。权限判定、文件内联范围、抽取规则
这三处，改坏了不会立刻报错——发现的会是你的学生。

改这些用例之前先想清楚：是需求真的变了，还是只是想让测试通过。
